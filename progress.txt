## 3. Phase 1: Security Hardening & Data Protection Checkpoints

[x] SEC-01: Multi-Tenant Authorization Bypass Fixed
    - Implemented strict Bearer authentication dependency `get_current_user` in `app/auth.py`.
    - Refactored all `/api/v1/user/*` endpoints (`/products`, `/purchase-orders`, `/purchase-orders/{po_id}/receive`, `/sales`, `/sales/summary`) to enforce `Depends(get_current_user)`.
    - Server now derives tenant identity strictly from authenticated session (`current_user["email"]`). Cross-tenant queries/mutations receive 403 Forbidden; unauthenticated requests receive 401 Unauthorized.

[x] SEC-02: PBKDF2-HMAC-SHA256 Password Hashing & Login Migration
    - Implemented `hash_password` and `verify_password` in `app/auth.py` using PBKDF2-HMAC-SHA256 (100,000 iterations) with unique 16-byte random cryptographic salt (`secrets.token_hex(16)`).
    - Preserved legacy accounts with seamless zero-downtime login-time migration: verifies legacy SHA-256 hash and automatically upgrades `password_hash` to PBKDF2 upon successful login.
    - Removed plaintext password storage from `smartstock_accounts_registry` in `stitch/smartstock-bridge.js`.

[x] SEC-03: Cryptographically Secure Session Tokens & Revocation
    - Added `app_sessions` table and indexes in `app/db.py`.
    - Implemented `create_session` generating 256-bit random tokens (`secrets.token_hex(32)`) with 7-day expiration (`expires_at`).
    - Added `POST /api/v1/auth/logout` endpoint and `revoke_session` to invalidate active tokens.
    - Updated `get_current_user` with datetime-aware expiration validation and seamless migration for any active legacy tokens.

[x] SEC-04: Server-Side Gemini AI Assistant Proxy
    - Implemented authenticated `POST /api/v1/ai/assistant` in `app/main.py` reading `GEMINI_API_KEY` from server config (`app/config.py`).
    - Scopes business context strictly to `current_user["email"]`'s products and sales.
    - Preserves Gemini 2.5 Flash integration and intelligent local heuristic fallback.
    - Updated `stitch/smartstock-bridge.js` (and mobile asset bundles `SmartStock/stitch/` and `SmartStockAndroid/app/src/main/assets/stitch/`) to proxy requests through `/api/v1/ai/assistant`, eliminating browser API key exposure.

[x] SEC-05: CORS Restrictions
    - Updated `app/config.py` `ALLOWED_ORIGINS` to remove wildcard `"*"` and default to explicit trusted localhost/Supabase origins, configurable via `ALLOWED_ORIGINS` env var.
